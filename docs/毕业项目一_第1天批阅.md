**题目**：写 `fetcher.py` 完整模块（6点要求见考题）

**你的作答**（原文）：

import requests
import os

class ApiError(Exception):
    def __init__(self, status_code, message=""):
        self.status_code = status_code

def fetcher_top_repos(top: int)->list[dict]:
    GITHUB_API = "https://api.github.com/search/repositories"

        raise ApiError(resp.status_code)

**评分**：15/30 🔴（-15）

**建议**（逐条对照题目6点要求）：
| 题目要求 | 你的实现 | 判定 |
|---------|---------|:--:|
| 1. `fetch_top_repos` 函数名 | `fetcher_top_repos` | ❌ 名字不同，调用方会 ImportError |
| 2. 用 `os.getenv` 读 token | ✅ `os.getenv("GITHUB_TOKEN")` | ✅ |
| 3. 请求 GitHub API + sort=stars | ✅ | ✅（但缺 per_page） |
| 4. timeout=10，超时抛 ApiError | ✅ 结构有 | 🔴 Timeout 分支引用不存在的 `resp` → NameError |
| 5. 非2xx抛 ApiError 带状态码 | ✅ `ApiError(resp.status_code, resp.text)` | ✅ |
| 6. 返回 `data["items"]` | ✅ | ✅ |

**关键错误（3个必修）**：
1. **函数名**：`fetcher_top_repos` → `fetch_top_repos`（第1天考题第三题明确写了函数名）
2. **headers 拼写 + 格式**：`"Anthorization"` → `"Authorization"`，且 GitHub 要求 `f"token {token}"` 格式，直接传裸 token 会 **401 认证失败**。你的实现即便网络通也会被 GitHub 拒绝。
3. **漏了 `per_page=top`**：`top` 参数定义了但从未使用——请求会返回默认30条，而不是 top 条。
4. **异常类位置**：ApiError 应放 `src/exceptions.py`（你自己第5题的架构也这么写了），fetcher.py 里应 `from src.exceptions import ApiError`。

**参考实现（建议对照）**：
```python
# src/fetcher.py
import os
import requests
from src.exceptions import ApiError

GITHUB_API = "https://api.github.com/search/repositories"

def fetch_top_repos(top: int) -> list[dict]:
    """获取 GitHub 上最热门的 Python 仓库"""
    token = os.getenv("GITHUB_TOKEN")
    params = {"q": "language:python", "sort": "stars", "per_page": top}
    headers = {"Authorization": f"token {token}"}
    try:
        resp = requests.get(GITHUB_API, params=params, headers=headers, timeout=10)
        if resp.status_code != 200:
            raise ApiError(resp.status_code, resp.text)
        return resp.json()["items"]
    except requests.exceptions.Timeout:
        raise ApiError(0, "请求超时")
    except requests.exceptions.ConnectionError:
        raise ApiError(0, "网络连接失败")
```

**比较**：你的骨架思路正确（try/except + 状态码检查 + 自定义异常 + json解析），扣分集中在**细节准确度**——这正是真实项目里代码审查会拦下来的问题。函数名、headers、per_page 这三个都是"写对了框架、写错了细节"。
